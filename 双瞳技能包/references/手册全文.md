# 双瞳识图方案手册（本地 OCR + 百炼 VL 双引擎）

> 用途：让没有视觉能力的文本大模型也能"看图"——本地免费 OCR 先探路，阿里云百炼 Qwen 视觉模型负责"看懂"。
> 命名：双瞳 = 两只眼睛：一只是 Windows 自带 OCR（识字），一只是百炼 VL（识图），互为补充。
> 本目录 = 本文档所在文件夹（本文件夹可能被放在**任意位置**，一切以"本目录"为准）；API Key 见同目录 `模型.txt`（单行，UTF-8）。
> **本文档为自包含手册：任何新会话只需完整阅读本文件即可接手全部流程，无需其他对话上下文。**
> 初版：2026-08 · 依据：百炼官方文档与多轮实测

## 开始前必读：前置告知（人类用户，在填 Key、发图之前先看）

1. **图片会离开你的电脑**：识图意味着图片会被上传到阿里云百炼服务器处理。含隐私/敏感内容的图片（身份证、内部文件、隐私照片等）请自行权衡；AI 每次调用前必须再提醒一次。
2. **支持哪些图片格式**：PNG、JPEG 直接支持；WebP / BMP / GIF / TIFF 等请先用系统"画图"另存为 PNG 再交。AI **不得擅自转换或修改**用户文件。
3. **读不了就停**：无论哪个通道，图片打不开、格式不支持、模型拒绝 → AI 必须**立即停止**，告知原因，并给出方案选项（另存为 PNG 重交 / 换通道 / 用户文字描述），由用户选择，**不得自作主张**。
4. **Key 泄露怎么办**：若怀疑 Key 泄露（误发聊天、文档被分享等）→ 立即登录百炼控制台**吊销该 Key 并重新生成**，然后更新本目录 `模型.txt`。新 Key 建议使用可随时吊销的子 Key。
5. **模型槽位存哪**：AI 按环境自检第 5 项拉取模型列表后，用户确认的 A/B/C 实际模型码写入本目录 `槽位配置.txt`（AI 创建/更新）；**本文档只保留模板，AI 不得修改本文档正文里的模板**。

## 图片怎么交给 AI（重要，首次使用前先看）

聊天界面通常**不能直接上传图片**，AI 自带视觉能力也**不一定可用**。本方案统一采用"文件路径"方式交付图片。**注意：识图会把图片上传到阿里云服务器（见「开始前必读：前置告知」）。**

1. **方式一（推荐）**：把图片放进本目录 `图片` 子文件夹（不存在时让 AI 创建），然后告诉 AI 文件名即可；
2. **方式二**：图片放在任何文件夹，直接把完整路径告诉 AI；
3. **方式三（可选）**：让 AI 在桌面创建指向本目录 `图片` 文件夹的快捷方式，以后拖图进快捷方式即可（需用户同意后由 AI 代建）；
> 补充：使用内置截图工具时更简单——保存后图片代码自动进剪贴板，聊天里 Ctrl+V 粘贴给 AI 即可（见「截图工具」章节第 7 条）。
4. **通道由用户选择，AI 不得擅自决定**：若当前会话模型自带读图能力（如 `read_image` 可用），AI 必须先如实告知用户"自带视觉可用 + 其优缺点"（优点：零成本零审批直接读；缺点：效果依赖当前模型能力、跨会话/切换模型后可能失效），并同时列出备选通道（双瞳 OCR / VL），**由用户选择走哪条**；模型不支持自带视觉时，再按双瞳流程询问用户。
5. **自带视觉失败：立即停止并如实告知**：当用户选择"自带视觉"通道（或 AI 尝试用自身能力读图）但当前模型无法读取图片时，AI 必须**立即停止**，如实告知用户失败原因（如"当前模型不支持图片输入"），**不得擅自切换到其他通道，不得猜测或编造图片内容**；是否改用双瞳通道（OCR/VL）由用户决定。
6. **支持格式**：PNG、JPEG 直接支持；WebP / BMP / GIF / TIFF 等先转成 PNG 再交（系统"画图"另存为即可），AI 不擅自转换用户文件。
7. **读不了立即停止**：图片打不开、格式不支持、模型拒绝 → 立即停止、告知原因、给出方案选项由用户选（另存为 PNG 重交 / 换通道 / 文字描述），**不得自作主张**。

## 截图工具（内置组件，可选使用）

> 工具位置：本目录 `工具\`（`双瞳截图.ps1` 主工具、`双瞳托盘.ps1` 常驻托盘、`ui.txt` 界面文字、`hotkey.cfg` 热键配置、`DuoPupil.exe` 干净启动器、`双瞳.ico` 图标）。
> 全程本地、免费、零联网；无开机自启、无残留。

### 功能一览

- 面板（双击桌面「双瞳」或让 AI 运行）：区域截图 / 全屏截图 / **驻留托盘** / 打开图片文件夹 / 快捷键说明 / 快捷键设置；右上角 图钉(置顶) / 最小化 / 关闭；
- 截图流程（微信式）：拖拽框选（绿框 + 外部压暗 + 尺寸标签在选框右上角）→ 松手后可**按住选框内部移动**、框外按下可重新框选 → 选框右下角三键【确认】【文字提取】【退出】；单击/回车=全屏，Esc=退出；

- 文字提取：保存同上 + 深色文字窗（一键复制）；
- 窗口：深色主题、可拖动、可最小化。

### 热键机制（v2.1）

- 组合键存于本目录 `工具\hotkey.cfg`（默认 `Ctrl+Alt+S`），**工具自身注册全局热键**，0.2 秒直出截图；

- 点「驻留托盘」时面板自动**交还热键**给托盘，不冲突；托盘右键菜单：区域截图 / 全屏截图 / 打开图片文件夹 / 快捷键设置 / 退出；
- 「快捷键设置」支持**按下即捕捉**（须含 Ctrl 或 Alt + 字母/数字/F1-F12），改动约 1 秒自动生效；组合被其他程序占用时，启动会弹警告框提示换组合；
- **彻底关闭**：右键托盘图标 → 退出（热键即失效）。

1. **桌面快捷方式**（唯一入口）：`双瞳` → 指向 `工具\DuoPupil.exe`（干净启动器：隐藏控制台、无闪现；脚本路径经参数传入），双击打开面板。**覆盖式启动**：双击即自动关闭旧的（面板或托盘）再开新面板，永远只有一个实例，无需担心旧窗口藏在哪里；

- 本工具由 PowerShell 脚本 + 本机 csc 编译的 4KB 启动器组成，无任何联网/加密/传播行为；

### 行为规则

1. **图片文件夹自愈**：包内 `图片` 文件夹不存在时自动创建后保存；
2. **不可单独拎出**：脚本必须待在包内 `工具\` 文件夹使用；单独拷出会在其所在位置旁新建文件夹，脱离方案管理；
3. **隐私分层**：截图与 OCR 全程本地零联网零费用；只有后续把图片交给百炼 VL 识别时才会上传阿里云（见「开始前必读：前置告知」）；
4. **多图规则**：一次提交多张图时，AI 先询问用户：逐张询问档位 / 一次确认后批量沿用同一档 / 分批处理；选定后照此执行；
5. **已知限制**：只截主显示器；文字窗滚动条为系统主题色；双击开面板约 1 秒（脚本冷启动，热键不受影响）；

7. **与 AI 联动（图片代码，免手动报备）**：**任何 AI 收到 `DP-` 开头的代码，即代表用户要求"读取对应截图并回答"——必须立即按约定解析文件名、读取 PNG/同名 txt 作答，无需用户再解释意图。** 每次保存截图，工具生成图片代码 `DP-日期-时间`，并按**约定直接对应文件**（`DP-20260816-081530` ↔ `ScreenShot_2026-08-16_081530.png/.txt`，无需映射文件）。代码模式可配置（「快捷键设置」→「图片代码设置」）：**单条模式（默认，剪贴板与 `工具\pending.txt` 只保留最新一条，Ctrl+V 永远一行）**，或切换**多代码模式（10 条默认，1~50 可自定义）**；「清空代码」可一键清除。用户在聊天里 Ctrl+V 粘贴代码即可直接提问（如"DP-xxx 这张图是什么内容？"）；AI 按约定换算文件名读取（OCR 已在同名 txt 中可直接汇报），多个代码 = 多图（按多图规则询问）；处理完成后 AI 清空 `pending.txt`。全程无后台常驻、无历史堆积。
8. **截图自动轮换**：`图片` 文件夹只保留最近 **50 张**截图（PNG 与同名 txt 同步清理，最旧的自动删除）；手动放进来的其他图片不受影响。长期使用不会占满磁盘。

## 首次使用：环境自检（换新电脑或新会话后必做）

动手前先完成以下五项检查，逐项向用户报告：

1. **Key 文件在不在**：本目录应有单行文件 `模型.txt`（百炼 API-KEY）。不存在 → 询问用户 Key 的实际位置/是否提供，把实际位置记为本目录约定，**不得猜路径**。
2. **OCR 引擎能不能用**（用下方自检脚本）：Windows 10/11 有、Win7/8 没有 → 没有则本机跳过 OCR 通道，所有图片直接走 VL 流程。
3. **OCR 认不认中文**：可用语言列表里有没有 `zh-Hans`。没有 → 提示用户去"设置→语言"免费添加中文语言包；装好前中文图走 VL，OCR 只用于英文图。
4. **网络/权限规矩**：确认本环境发起外网 HTTPS 请求是否需要特殊放行（如沙箱提权审批）。需要 → 每次调用按「权限预告知」先预告再执行；不需要（普通环境）→ 直接执行。
5. **模型可用性确认（自动优先，无需用户手动复制）**：用下方脚本 + 本目录 `模型.txt` 的 Key 调用模型列表接口，自动拉取账号可用模型，筛选视觉类（型号含 `vl`/`omni`/`vision`）作为候选，由 AI 推荐 A/B/C 三档（旗舰/日常/兜底），**用户确认后**把实际模型码写入本目录 `槽位配置.txt`（不修改本文档模板）。接口拉取失败 → 退回手动：请用户登录百炼控制台（见文末链接）复制模型名。

### 自动拉取模型列表脚本（复制即用，实测 HTTP 200 通过）

```powershell
$dir     = '<本目录绝对路径，与本文档同目录>'
$keyFile = Join-Path $dir '模型.txt'
$apiKey  = [IO.File]::ReadAllText($keyFile, [Text.Encoding]::UTF8).Trim()
$r = Invoke-WebRequest -Uri 'https://dashscope.aliyuncs.com/compatible-mode/v1/models' `
  -Method Get -Headers @{ Authorization = "Bearer $apiKey" } -TimeoutSec 60 -ErrorAction Stop
[IO.File]::WriteAllBytes((Join-Path $dir 'models.json'), $r.RawContentStream.ToArray())
Write-Output "HTTP $($r.StatusCode) saved $($r.RawContentStream.Length) bytes"
```

> 取回后用文件工具读 `models.json`，筛出含 `vl`/`omni`/`vision` 的型号即为视觉候选；按"旗舰/日常/兜底"推荐三档后请用户确认，确认结果写入 `槽位配置.txt`。
> 实测记录（某示例账号，2026-08）：接口返回 238 个模型，视觉类 26 个（`qwen-vl-plus`/`qwen-vl-max`/`qwen-vl-ocr`/`qwen3-vl-*`/`qwen*-omni-*` 等）。注意 `qwen-vl-ocr` 是专门的 OCR 视觉模型，纯文字图可优先考虑，与本机免费 OCR 互补。

### 新用户设置 Key（三步，只需做一次）

1. 在本目录新建文本文件，命名为 `模型.txt`；
2. 打开文件，把百炼 API-KEY **单行**粘贴进去（不带引号、空格或任何说明文字），保存为 UTF-8；
3. 验证：文件内容应恰好是一个 `sk-` 开头的 Key，不含其他内容。

> 安全约定：Key 只存在于 `模型.txt`，**永不写进本文档、永不粘贴进聊天**；本文档可随意分享，`模型.txt` 绝不外传。
> 暂时没有 Key：去百炼控制台 → API-KEY 管理页生成，建议用可随时吊销的子 Key。

### 自检脚本（任何 Windows 均可安全运行，复制即用）

```powershell
Write-Output "--- OCR engine check ---"
try {
  Add-Type -AssemblyName System.Runtime.WindowsRuntime
  $null = [Windows.Media.Ocr.OcrEngine,Windows.Foundation,ContentType=WindowsRuntime]
  $langs = [Windows.Media.Ocr.OcrEngine]::AvailableRecognizerLanguages
  Write-Output "OCR available: YES"
  Write-Output "languages: $($langs.LanguageTag -join ', ')"
  $hasZh = ($langs.LanguageTag | Where-Object { $_ -like 'zh-Hans*' })
  Write-Output "chinese(zh-Hans): $([bool]$hasZh)"
} catch {
  Write-Output "OCR available: NO ($($_.Exception.Message))"
}
```

## 选型结果与档位模板（新用户按自己账号调整）

> **A/B/C 是档位模板，不是固定模型**：下表默认码来自某示例账号，仅作参考；**实际生效的槽位以本目录 `槽位配置.txt` 为准**。
> 新用户请把各档替换为自己百炼账号中实际可用的模型码——A=日常档（快、省）、B=旗舰档（最强）、C=兜底档。
> 换档逻辑不变：日常默认 A，复杂图升 B，A/B 不可用降 C。

| 槽位 | 默认模型码（示例，可替换） | 档位 | 选择理由 |
|------|--------------------------|------|----------|
| A | `qwen3.5-omni-flash` | 日常档（快、省） | 同代快速版，日常识图完全够用，速度快、成本低（推荐默认） |
| B | `qwen3.5-omni-plus` | 旗舰档（最强） | 同代旗舰，识图精度最高，复杂图像/文字密集场景用它 |
| C | `qwen3-omni-flash` | 兜底档 | 上一代快速版，A/B 不可用/报错时降级使用 |

> 参考：示例账号里更早世代的 `qwen-omni-turbo`、`qwen2.5-omni-7b` 识图能力较弱，不选；日期后缀快照版（如 `...-2026-03-15`）与无后缀版本能力一致，只是固定快照。

## 通用 API 信息（所有模型通用）

### 接口地址（OpenAI 兼容模式，推荐）

```
POST https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions
```

### 请求头

```
Authorization: Bearer <API Key，读自本目录 模型.txt>
Content-Type: application/json
```

### 请求体模板（识图）

```json
{
  "model": "qwen3.5-omni-flash",
  "modalities": ["text"],
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "image_url",
          "image_url": {
            "url": "data:image/jpeg;base64,<图片base64编码>"
          }
        },
        {
          "type": "text",
          "text": "请详细描述这张图片的内容。"
        }
      ]
    }
  ]
}
```

### 关键参数说明

- `modalities: ["text"]`：**必须加**。omni 模型默认会返回语音+文字，加了这个参数后只返回纯文字结果，识图场景必填。
- `image_url.url`：支持 `data:image/jpeg;base64,...` 内嵌，也支持公网图片 URL；PNG 图把 mime 换成 `image/png`。
- 图片大小：常规截图/照片直接 base64 内嵌即可，单图不超过数 MB 都无问题。

### 备选：百炼原生接口（非 OpenAI 兼容）

```
POST https://dashscope.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation
```

请求体模型码相同，content 结构一致，需要额外传 `X-DashScope-SSE: disable` 头关流式。一般用上面的兼容模式即可。

## 第 0 步：本地 OCR 探路（免费，优先于一切 VL 调用）

> 实测结论（2026-08）：Windows 自带 OCR 与百炼 VL 各有胜负，组合使用最优——
> OCR 免费秒出，但会读错艺术字（Blender→31ender、Marmoset→MärmOSet）；VL 覆盖更全，但小字会幻觉（同一张图三次读成 711 / FLU / PLU，版本号不可全信）；关键文字应两者对照。

### 路由规则（收到图片后强制执行）

> **截图工具的图免重复 OCR**：若图片来自内置截图工具（DP 代码，或同名 `.txt` 已存在），OCR 在保存时已完成——直接读同名 txt 进入第 2/3 步，跳过第 1 步。

1. **先跑本地 Windows OCR**（零费用、零网络、无需审批）；
2. **OCR 有文字**（截图/文档类）→ 先把 OCR 结果交付用户，并询问"是否还需要 VL 视觉分析"（如需，走下方 A/B/C 流程）；
3. **OCR 无文字**（插画/照片类）→ 直接进入 A/B/C 询问流程，调用 VL；
4. OCR 与 VL 结果不一致时，**两者并列展示，不擅自断定谁对**。

### Windows 自带 OCR 脚本（零安装，复制即用）

```powershell
Add-Type -AssemblyName System.Runtime.WindowsRuntime
$null = [Windows.Storage.StorageFile,Windows.Storage,ContentType=WindowsRuntime]
$null = [Windows.Media.Ocr.OcrEngine,Windows.Foundation,ContentType=WindowsRuntime]
$null = [Windows.Graphics.Imaging.BitmapDecoder,Windows.Foundation,ContentType=WindowsRuntime]
$null = [Windows.Globalization.Language,Windows.Globalization,ContentType=WindowsRuntime]

$asTaskGeneric = ([System.WindowsRuntimeSystemExtensions].GetMethods() | Where-Object { $_.Name -eq 'AsTask' -and $_.GetParameters().Count -eq 1 -and $_.GetParameters()[0].ParameterType.Name -eq 'IAsyncOperation`1' })[0]
function Await($WinRtTask, $ResultType) {
  $asTask = $asTaskGeneric.MakeGenericMethod($ResultType)
  $netTask = $asTask.Invoke($null, @($WinRtTask))
  $netTask.Wait(-1) | Out-Null
  $netTask.Result
}

$path = '<图片完整路径>'
$file = Await ([Windows.Storage.StorageFile]::GetFileFromPathAsync($path)) ([Windows.Storage.StorageFile])
$stream = Await ($file.OpenAsync([Windows.Storage.FileAccessMode]::Read)) ([Windows.Storage.Streams.IRandomAccessStream])
$decoder = Await ([Windows.Graphics.Imaging.BitmapDecoder]::CreateAsync($stream)) ([Windows.Graphics.Imaging.BitmapDecoder])
$bitmap = Await ($decoder.GetSoftwareBitmapAsync()) ([Windows.Graphics.Imaging.SoftwareBitmap])

$engine = [Windows.Media.Ocr.OcrEngine]::TryCreateFromUserProfileLanguages()
if (-not $engine) {
  $lang = New-Object Windows.Globalization.Language 'zh-Hans'
  $engine = [Windows.Media.Ocr.OcrEngine]::TryCreateFromLanguage($lang)
}
if (-not $engine) { Write-Output 'OCR ENGINE UNAVAILABLE'; exit 0 }
$result = Await ($engine.RecognizeAsync($bitmap)) ([Windows.Media.Ocr.OcrResult])
Write-Output "LINES: $($result.Lines.Count)"
foreach ($line in $result.Lines) { Write-Output $line.Text }
```

> 未来可选升级：安装 `@liustack/modlens`（npm CLI）补充版面布局+语义标签；必须用户亲手安装或明确授权，代理不得擅自安装第三方包。

1. 向用户说明本次准备调用的模型（默认推荐 A），并给出 3 个选项：

| B | 旗舰档（最强） | 识图精度最高；复杂图片、密集文字用 |
| C | 兜底档 | A/B 不可用或报错时降级备选 |

> A/B/C 各档的实际模型码以本目录 `槽位配置.txt` 为准（首次自检时由用户确认后写入）；手册表格仅为模板。

2. 用户明确选择 A/B/C，或回复"默认"（等同选 A），才可发起调用。
3. 调用失败时：向用户说明失败原因，再询问是否换下一个档位——**不得自动连续切换模型**（详见下方「失败处理细则」）。

## 失败处理细则（强制）

### 错误码对照表（收到非 200 时先对表再报告）

| HTTP/错误码 | 含义 | 处理 |
|-------------|------|------|
| 200 | 成功 | 正常交付结果 |
| 429 + 限流（Throttling） | 临时限流，额度未用完 | 告知用户"暂时限流"，稍等重试即可，不换模型 |
| 429 + 额度耗尽/欠费 | 该档位额度用完 | 报告用户，询问是否换档位 |
| ModelNotOpen（模型未开通） | 该模型未在账号开通 | 报告用户：去百炼控制台开通，或换档位 |
| InvalidApiKey / 401 | Key 无效 | 报告用户：检查本目录 `模型.txt` 里的 Key 或重新生成 |
| 5xx | 百炼服务端故障 | 报告用户，稍后重试或换档位 |
| 请求发不出去（断网/超时/DNS） | 网络层失败，未到达服务器 | 报告用户具体错误，稍后重试或换网络，不换模型 |

### 逐档询问流程（不自动降级）

1. 用户选定的档位调用失败 → **立即停止**，报告：档位、错误码、含义（对上表）。
2. 询问用户：换到哪一档（列出剩余档位），或先暂停。
3. 用户确认后才调用新档位。**任何情况下不得自动连续切换模型。**

### ABC 全部失败时的四条出路

1. 去百炼控制台充值/调整额度（额度用完 ≠ Key 失效，充值即可继续）；
2. 检查模型是否未开通（ModelNotOpen → 开通即可，不额外花钱）；
3. 换列表中的其他全模态模型或重新生成 Key；
4. 兜底：用户用文字描述图片，直接继续任务。

### 每次调用后的 token 报告（强制）

每次成功调用后，必须读取响应中的 `usage` 字段并向用户报告：

- 本次消耗：`prompt_tokens` / `completion_tokens` / `total_tokens`（有细分时含 image/text 明细）；
- 本会话累计消耗：把历次 `total_tokens` 求和报告。

> 报告示例：`本次消耗 1500 token（图片 1026 + 提示文本 40 + 输出 434），本会话累计 3500 token`。

## 已验证的标准调用流程（UTF-8 安全版，必用）

> 背景：Windows PowerShell 控制台常见 GBK 码页。两个已踩过的坑：
> ① 中文提示词直接写进命令行 → 发送时变成 "?"，模型只给简短回复；
> ② 响应中文直接打印控制台 → 乱码。
> 因此本流程强制"全程文件 + UTF-8"，已在真实调用中验证通过。

### 标准三步

1. **提示词写文件**：把要问的中文提示词写入本目录 `prompt.txt`（UTF-8，用文件工具写，禁止直接内嵌命令行）。
2. **调用走模板**：用下方脚本调用，响应原始字节直接落盘本目录 `resp.json`，不在控制台打印中文。
3. **读结果**：用读文件工具（UTF-8）读 `resp.json` 取 `choices[0].message.content`，整理后交付；如需存档再写入本目录 `图片识别结果.md`（多图按图片名分文件存档，识别前先查存档复用，避免重复计费）。

### 标准调用脚本（复制即用，实测通过版）

```powershell
$dir        = '<本目录绝对路径，与本文档同目录>'
$keyFile    = Join-Path $dir '模型.txt'
$promptFile = Join-Path $dir 'prompt.txt'
$imgFile    = '<图片完整路径>'
$respFile   = Join-Path $dir 'resp.json'

# 全部用 [IO.File] 读取，保证纯字符串（避免部分环境给字符串附加扩展属性导致 JSON 变形）
$apiKey = [IO.File]::ReadAllText($keyFile, [Text.Encoding]::UTF8).Trim()
$prompt = [IO.File]::ReadAllText($promptFile, [Text.Encoding]::UTF8).Trim()
$imgB64 = [Convert]::ToBase64String([IO.File]::ReadAllBytes($imgFile))

# 提示词先单独转成 JSON 字符串（自动转义），再手工拼装请求体
$promptJson = $prompt | ConvertTo-Json -Compress
$mime = if ($imgFile.ToLower().EndsWith('.png')) { 'image/png' } else { 'image/jpeg' }
$json = '{"model":"<A/B/C 槽位实际模型码>","modalities":["text"],"messages":[{"role":"user","content":[{"type":"image_url","image_url":{"url":"data:' + $mime + ';base64,' + $imgB64 + '"}},{"type":"text","text":' + $promptJson + '}]}]}'

# 请求体以 UTF-8 字节数组发送（杜绝中文变 "?"）；响应原始字节落盘（杜绝控制台乱码）
$r = Invoke-WebRequest -Uri 'https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions' `
  -Method Post -Headers @{ Authorization = "Bearer $apiKey" } `
  -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($json)) -TimeoutSec 90

[IO.File]::WriteAllBytes($respFile, $r.RawContentStream.ToArray())
Write-Output "HTTP $($r.StatusCode) saved $($r.RawContentStream.Length) bytes"
```

> 模型码填用户选定档位的实际模型码（以 `槽位配置.txt` 为准）；调用前仍须按"调用规则"先询问用户并取得确认。
> 坑记录：某运行环境找不到 `[Net.Http.HttpClient]` 类型，因此统一使用上述 `Invoke-WebRequest` + UTF-8 字节方案（已实测 HTTP 200 成功）。

## 跨平台打包与安装（发布者与用户须知）

### 已知坑位与规避（打包/分发时必须遵守）

1. **脚本仅限 Windows**：OCR 脚本与调用脚本依赖 Windows 10/11 + PowerShell，在 Linux/Mac 会报错。技能包必须标注"运行环境：Windows + PowerShell"；非 Windows 用户只继承本手册规则、自行实现脚本。
2. **SKILL.md 头部格式**：`name` 只能小写字母+连字符，`description` 单行，正文不得出现孤立的 `---` 分隔线，否则平台加载器解析失败——严格按官方样例格式书写。
3. **编码纪律**：所有文件一律 UTF-8（无 BOM），沿用本方案"全程 UTF-8"流程，避免乱码或解析错误。
4. **SKILL.md 瘦身**：只放规则主干与触发描述；脚本全文、错误码对照表等细节放 `references/`，需要时再读——避免每次触发整包塞进上下文。
5. **安装位置各平台不同**：装错位置的表现是"读不到/不触发"，而不是报错。README 必须写明各平台的安装路径（见下）。
6. **区域网络**：DashScope 是阿里云国内服务，海外网络可能慢或不稳定——与本方案打包无关，用户须知悉。

### 安装方式（链接 → 下载 → 放目录 → 自动生效）

- **发链接即可安装**：AI 可从 GitHub 链接下载技能包，放入技能根目录即完成安装（下载与写入目录按环境规则提权审批）。
- **填写卡先问后开**：安装完成后，AI **先询问用户**"是否现在打开 `模型.txt` 填写卡？"（填写卡含简介、填写路径、百炼 API 获取链接）——用户确认后才打开，不擅自弹出；用户拒绝则跳过，随时说"打开填写卡"可再开。用户按卡替换为 Key 并保存后，AI 校验（单行、`sk-` 开头）再继续。原「新用户设置 Key（三步）」的第 1 步"新建文件"以预置卡为准。
- **DSH 技能根目录**（官方文件系统提供者，按优先级扫描）：
  1. `<项目根>\.dsh\skills\`（项目级；项目根 = 最近含 `.git` 的上级目录）
  2. `<项目根>\.agents\skills\`（项目级，跨工具通用）
  3. `%USERPROFILE%\.dsh\skills\`（**用户级，推荐：一次安装全局生效**）
  4. `%USERPROFILE%\.agents\skills\`（用户级，跨工具通用）
- **自动生效**：DSH 自带文件监听（watch），放入新技能后自动登记；当前会话的技能表是启动时快照，最稳做法是**新开一个会话**使用。
- **技能文件**：目录内放 `SKILL.md`（或平铺 Markdown），`references/` 等资源同目录存放。
- **Claude Code / Claude**：放入项目 `.claude/skills/` 或用户级 `~/.claude/skills/`。
- **其他聊天环境**：无需安装——直接让 AI 读本手册（手册即自包含规则）。
- **万能兜底**：任何平台都可用开场白一句话："请阅读 <文件夹路径>\双瞳识图方案手册.md，并按「首次使用：环境自检」执行。" 不依赖任何技能机制。
